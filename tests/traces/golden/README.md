# tests/traces/golden — agent trace goldens

`scripts/scan/trace_eval_check.py` (scan step 5/7) replays every `*.json`
golden in this directory against the trace it points at and asserts on
tool sequence, terminal state, and (since 2026-09-14) that at least one tool
failed. The goldens close the loop on `AgentTraceRecorder` output: produce →
consume.

## Two shapes

**Inline (`trace_lines`)** — the trace is embedded in the golden. Used by the
two `selftest-*.json` cases, which exist to keep the *evaluator* honest rather
than to test the app.

**Referenced (`trace`)** — the golden points at a real `.jsonl` file, usually
under `traces/`. Use this for anything that encodes a production behaviour: the
trace is then a plain artifact that can be diffed, replayed with other tools,
and replaced by a device recording later.

## Fault goldens (2026-09-14)

Both shipped with the update/agent hardening batch. Each one only goes red when
the specific guard it covers is removed — that was verified by mutation (see
below), not assumed.

| golden | fault it encodes | regression signal |
| --- | --- | --- |
| `truncated-tool-call-refused.json` | a `file_write` call cut off by the output ceiling (`finish_reason=length`) must be refused, not executed with half its arguments | `tools` grows to `[file_write, file_write]` the moment the refusal stops happening |
| `offloaded-payload-refused.json` | a `[CONTEXT OFFLOADED] … saved to:` stub replayed into a write payload must be refused (writing it truncates a real file to a placeholder) | `some_tool_failed` stops holding once the stub write succeeds again |

Note `all_tools_succeed: false` **cannot** express the second case: a falsy
`expect` value disables the assertion instead of inverting it, so the case would
pass with the guard gone. Hence the separate `some_tool_failed` assertion.

## Provenance of the shipped `.jsonl` files

`traces/truncated-tool-call-refused.jsonl` and
`traces/offloaded-payload-refused.jsonl` were **generated by the verbatim
production `AgentTraceRecorder`** (`src/android/app/src/main/java/com/rikkaminis/app/tools/AgentTraceRecorder.kt`)
driven from a scratch `main()` in the sandbox — not hand-written JSON. Field
set, ordering, truncation caps and the `trace_start`/`trace_end` shapes are
therefore the recorder's own, which is what keeps them parseable by
`trace_eval_check.py` and by the in-app trace viewer.

Their *event sequences* are authored to mirror the production call sites:

* run open / phase transitions / budget consumption → `AgentLoopEngine`
* `tool_call` → budget(`tool_calls`) → `ToolStarted` → acquire `tool_slot` →
  release → `tool_result` → `ToolFinished` → `ChatPromptAndTools.executeToolWithTrace`
* `session_slot` lease + `endRun` → `ChatAgentTraceObserver.t7EndRun`

The refusal *messages* are copied verbatim from the guards
(`OffloadedPayloadGuard.refusalMessage`, `TruncatedToolCallPolicy.rejectionReason`)
so a message change shows up as a diff in a committed artefact.

## Adding a trace from a real device run

1. On the device, a finished run leaves `agent-<timestamp>.jsonl` in the
   session's `.traces/` directory (retention-pruned; only the newest few stay).
   Pull the file out while that session is still around.
2. Strip or accept the prompt/provider content — the recorder already redacts
   secrets, but a real prompt may still carry user text. Trim `prompt` /
   `prompt_preview` if the golden does not need them.
3. Copy it to `tests/traces/golden/traces/<name>.jsonl`, add a sibling
   `<name>.json` golden with `"trace": "tests/traces/golden/traces/<name>.jsonl"`
   and the assertions you actually want to pin.
4. Run `python3 scripts/scan/trace_eval_check.py .` — if the assertions do not
   describe the recording, the run tells you exactly which one disagreed.

## Verifying a new golden has teeth

A golden that passes is worth nothing until you have seen it fail for the right
reason. Cheapest check: copy `tests/traces/golden/` into a scratch tree, mutate
the copy so the fault it guards *stops* happening (drop the failing
`tool_result`, add the extra executed call, delete `trace_end`), and run
`python3 scripts/scan/trace_eval_check.py <scratch-tree>`. `test_scan.py` keeps
a fixture version of this for the evaluator's own assertions.
