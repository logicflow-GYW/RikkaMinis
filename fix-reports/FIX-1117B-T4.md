## 2 先证结论：两条都成立，真跑取终态（非纸面推演）

沙箱里 `uid=0` 是 PRoot 伪造的，因此**不用 root 跑**：以 `su nobody -s /bin/sh` 起 JVM，让内核真的执行 mode 位检查（`chmod 000` 后 `ls` 报 Permission denied，确认内核在场）。探针直接把 `RootfsResetFilesTest` 整个类编到两臂产物上跑，避免"探针自己实现一遍逻辑"的漂移。

**C1.1（数据丢失）成立** —— 修复前代码，`rootfs` 自身 `chmod 000`、内含 `.l2s-backing/kept-model.bin`：

```
java.nio.file.NoSuchFileException: .../files-nosearch/alpine-rootfs/.l2s-backing/kept-model.bin
[WARN] [RootfsReset] reset could not remove .../alpine-rootfs/.l2s-backing; the next extraction writes over it
```

即：用户所有伪硬链接目标内容的唯一副本被删掉。机制逐条对上报告——
`Files.exists(backing, NOFOLLOW_LINKS)` 在父目录无 `+x` 时 `lstat` 抛 `EACCES`，`Files.exists` 吞掉异常返回 **false** ⇒ `preserveBacking = false` ⇒ `walkFileTree(root)` 打不开 root ⇒ `visitFileFailed(root)` 以 `skipSubtree = null` 进子树删除 ⇒ 整棵删。

**C1.2（作用域外 chmod / 删掉 scope root）成立** —— 修复前，`rootfs` `chmod 0111`（`+x` 无 `+r`），父目录先降到 `0555` 作为探针：

```
AssertionError: nothing above the rootfs may be chmod-ed
  expected:<[OWNER_EXECUTE, OWNER_READ]> but was:<[OWNER_EXECUTE, OWNER_READ, OWNER_WRITE]>
[WARN] [RootfsReset] reset could not remove .../alpine-rootfs; the next extraction writes over it
```

`rootfsDir.parent` 被补上 `u+w` —— 那是 app 私有 files 目录，装着数据库、prefs 和所有其它数据。无 backing 时更直接：

```
AssertionError: the rootfs directory itself must survive
```

**三处会踩坑的地方（都实测踩到了，写下来免得下一轮重踩）**

1. **第一条 C1.1 断言差点假绿**：本沙箱的 PRoot 把 `.l2s.*` 叶子从 `readdir` 里隐藏，修复前删 `.l2s-backing` 会以 `ENOTEMPTY` 失败 ⇒ 目录本身"幸存"，用 `.l2s.` 命名的探针在 pre 臂上是**绿的**。加了一个普通名 `kept-model.bin` 才把 pre 臂压红（它的消失就证明 `skipSubtree` 为 null，即 `preserveBacking == false`）。CI 的 runner 不是 PRoot，`.l2s.` 那条断言在那边才是全牙。
2. **C1.2 的"无 backing"臂必须用 `0111` 而不是 `000`**：`000` 会让 C1.1 的修复顺手把 root 恢复可读，`visitFileFailed(root)` 根本不触发，这条臂就变成测 C1.1 的副作用、测不到"作用域根不自删"。改 `0111` 才真正走到那条路径（变异 M2 的单红即是证明）。
3. **KDoc 链接 `[C1.1]` 让三个编译 job 全红，本地却编过**：CI `#3207` 三个 job 同时报 `RootfsResetFiles.kt:107:7 Closing bracket expected`。该串来自 `org/jetbrains/kotlin/kdoc/parser/KDocLinkParser`（在 2.1.0 编译器 jar 里 grep 到唯一命中），即 **KDoc 链接语法**：链接体必须是限定名，`C1` 之后跟 `.1` 不是合法标识符。CLI `kotlinc` 根本不解析 KDoc ⇒ 本地同版本、同字节编译零输出零告警（`EXIT=0`），只有 **KSP** 走 KDoc 解析才炸。修法：把 `[C1.1]` 写成纯文本 / 反引号；同时加了一条机械判据（正则 `^[A-Za-z_][A-Za-z0-9_]*(?:\.[^A-Za-z_])`）扫两个文件的全部 KDoc 链接，其余 `[C-F01]` / `[incr1116-CD F-04]` 这类"标识符后跟 `-` / 空格"的写法解析器会就地放弃、不报错，故一直绿。

## 3 修法（一句话）

**C1.1**：把"backing 是否存在"从布尔改成三态（`ABSENT` / `PRESENT` / `UNKNOWN`），用 `Files.readAttributes` 让**异常类型**承载"不存在 vs 问不出"；问不出时先给 scope root 补属主权限再问一次，仍是 `UNKNOWN` 就按"存在"处理并落 warning —— 只有权威的 `ABSENT` 才允许整棵删除。
**C1.2**：子树删除显式携带 `scopeRoot`，**永不自删 scope root**（没有开关可覆盖）；`restoreOwnerAccess` 增加作用域守卫，`scopeRoot` 之外的路径一律不 chmod（包括删除失败时的父目录兜底）。

关键点：

- **`Files.exists` 换掉的理由写进 KDoc**：它对 `ENOENT` 与 `EACCES` 回答同一个 false，而两者在这里后果完全相反。三态不是洁癖，是不让"看一眼失败"变成"删掉全部"。
- **fail-safe 方向**：判不出来就留（跳过一个不存在的目录成本为零，删掉一个存在的目录不可撤销）；不选"拒绝重置"，因为那会让一棵谁也看不清的树把重置永久卡死，而解压仍然要发生。
- **unsafe backing 校验只在 `PRESENT` 时做**：`UNKNOWN` 时我们连它是什么都不知道，此时报"unsafe"会是又一个把不确定当成事实的错；跳过它反而更安全（不会跟随、不会删除）。
- **作用域守卫是叠加的两层**：作用域根守卫挡住唯一一条"到 root 之外"的路径，chmod 守卫再兜一次底（M3/M5 两个变异正好证明这层是冗余但有效的，见 §4.3）。
- **不加死参数**：没有 `deleteScope: Boolean`（恒 false 的参数是负债），改为 `current != scopeRoot` + KDoc 说明"要删 scope root 是另一种操作，不是本函数的开关"。
- **保留既有契约**：`visitFileFailed` 仍返回 `CONTINUE`；`preserveBacking && file == backing` 仍直接跳过；`postVisitDirectory` 仍 `dir != root`；符号链接仍不 chmod 不跟随。

## 5 影响面与风险

- **正常路径行为不变**：backing 存在 ⇒ `PRESENT`（与旧 `Files.exists` 同结论）；不存在 ⇒ `ABSENT`（同结论）；`chmod 000` 之外的一切落到原有分支。变的只有"问不出"这一格。
- **仅在本文件内**：三个 private 函数签名变化（`deleteRestoringOwnerWrite` / `deleteTreeRestoringOwnerAccess` / `restoreOwnerAccess` 各加 `scopeRoot`），调用点全部在同一文件内，已逐一改齐（`grep` 核过 5 处调用）。
- **最坏新增风险**：`UNKNOWN` 时保留 backing ⇒ 该次重置会少删一个 `.l2s-backing`（换新 rootfs 后它本来就该保留），代价为零。
- **错误信息面**：新增一条 warning（`reset cannot tell whether … exists; preserving it for this run`），只在真正的"看不了"时出现。

## 7 真机待验（本轮未装机，留给合并后的版本）

1. 正常重装 rootfs（有 `.l2s-backing`）：伪硬链接文件内容仍可读，沙箱可启动。
2. 制造 `chmod 000` 的 rootfs 目录（含 backing）后触发重装：`.l2s-backing` 与其下文件仍在、rootfs 目录仍在、日志出现 `cannot tell whether … exists` 或直接静默成功（取决于内核是否让探针看到 `EACCES`）。
3. 制造 `chmod 0111` 的 rootfs 目录后触发重装：`files/` 目录权限不变（`ls -ld` 对照），rootfs 目录仍在，日志无 `could not remove …/alpine-rootfs`。
4. 无 backing 的 `chmod 0111` rootfs：rootfs 目录必须仍在（旧版会被删掉）。
