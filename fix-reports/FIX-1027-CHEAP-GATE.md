## 1. 起因（用户报的症状，不是代码 bug）

用户：「最近修这个应用的阻力越来越大」，并指出最大成本是「云端 CI 要跑 20 多分钟」。
取全史 3317 提交 + 2782 个 Actions run 做时间序列，结论是**非错觉**：

| 读数 | 9 月平台期 | 10-26 周 |
|---|---|---|
| 成功 run 中位时长 | 12.3–13.9 min | **22.8 min**（p90 25.2） |
| pre-build scan gate 步 | 0.07–0.29 min | **6.79 min**（max 9.30） |

单次 22.8 min 里约 **16.7 min 是与改动内容无关的固定税**。

## 2. 根因（成本结构，不是缺陷）

按 diff 类别实算 10-12..10-27 的 CI 消耗（逐 sha 分类，非抽样）：

| 类别 | run | CI 分钟 | 占比 | 中位 |
|---|---|---|---|---|
| 含生产改动 | 546 | 7907 | 68% | 15.2 |
| **纯装置（生产 0 行）** | **123** | **2356** | **20%** | **19.7** |
| 未合并/取消的废弃支 | 144 | 1381 | 12% | 12.5 |

抽 12 支纯装置支逐步骤看结论：**12/12 在扫描门以外的步骤全部恒绿**——src 一行没动，Gradle 5.8 + 单测 4.9 + instrumented 1.1 编的是它没改的代码，那 ~13 分钟不包含任何关于**这支改动**的信号。

仓库里本来就有两个更快的通道，但都没被用上：
- `scan-gate.yml` 绑 `on: pull_request`，而本仓工作流**从不开 PR** → 死代码；
- `scan-gate-push.yml`（main push，scan.sh + 夹具 = 实测 **6.78 min**）虽有 `workflow_dispatch`，但没有路由规则、也没有任何东西阻止「把廉价绿当成生产改动的停止节点」→ 从来没人往支上 dispatch 它。

## 3. 修法（3 文件 +210/−8）

1. `.github/workflows/scan-gate-push.yml`：把头注释改写成「分支通道」的契约（含实测依据），并新增 **Guard 步**（`if: github.ref_name != 'main'`）。main push 行为不变（仍是扫描器落 main 的见证路）。
2. `scripts/diag/cheap_gate_guard.py`（新，152 行）：判定 diff 是否**只**含装置路径。白名单 = `scripts/scan/**` `scripts/diag/**` `fix-reports/**` `docs/**` 根目录 `*.md` 以及本 workflow 文件自身。退出码：**0** 装置类 · **1** 越界（点名每条越界路径，要求改走 build-apk）· **2** 无法证明（无 token / API 失败 / compare 撞 300 文件上限）——**1 与 2 都红，但处置不同**；无法证明按 fail-closed 处理。三种取路径模式：CI 用 GitHub compare API（`main...<sha>`）、本地用 `--git-range`（三点，避免 main 前进被误算成支上改动）、离线用 `--paths-file`。
3. `BUILDING.md`：新增「Which channel to dispatch」小节 + 判据表。

**为什么这不拿证据换速度**：廉价通道的绿只覆盖「扫描门 + 夹具」，而守卫保证**只有扫描门+夹具可能失败的改动**才能拿它当停止节点。越界改动**拿不到绿**（16 秒拒付），所以不存在「廉价绿盖住没编译的代码」这条通路。

## 5. 未验证 / 残留

- **R1（P2，登记不修）**：守卫白名单与 `build-apk.yml` 的 `on.push.paths` 是**两份独立清单**，新增装置目录时可能只改一处。失效方向安全（少列 → 被迫走全量构建），所以按 装置比例纪律登记不建门；触发条件 = 第三次出现「新增 scripts/ 子目录」类改动。
- **R2（P2）**：compare API 的 300 文件上限——超大装置批（>300 文件）会 rc=2 强制走全量。当前批次形态 73 文件级，不触发；触发条件 = 首个 >300 文件的装置批出现。
- **R3**：本支只覆盖「装置支走哪道门」。**夹具自测仍是 5.25 min 的串行段（占廉价通道 73%）**——刀 2（test_scan 分片）未动，做掉后廉价通道可到 ~2.5 min、全量构建也同步省 ~4 min。
- **R4**：门数本身还在涨（14 天 +91 道）。实测利息 ≈ **每道门每次 run +4 秒**（scan 0.6s + 该门夹具 ~3 条 × 1.13s）；本轮降的是税率不是本金，装置预算/退役纪律仍未落地（109 道门退役数 = 0）。
- **未验证**：本支改的是 workflow 自身与一个纯 Python 脚本，**不涉 src/**，故未跑 build-apk（按新规则它也不该跑）。合入 main 后由 push 自动触发全量构建兜底。
