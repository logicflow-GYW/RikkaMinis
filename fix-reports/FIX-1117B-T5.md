### 2.2 C3.1（P1，门假阴性）

判据 `re.search(r"\breturn\b", failure_body)`。`@` 不属 `\w`，所以 `return@withContext` / `return@let`
满足它；而 `when` 外层套着 lambda（`withContext { … }` / `.let { … }`）时，带标签 return **只退出内层
lambda**，控制流仍落穿到 `when` 之后的 `onStateChange(HudState.SUCCESS, …)` —— 这正是本门存在的理由
（`RC-U12` / `incr1116-A F-06` 的 HUD 谎报）。先证：`DIRTY_SB_LABELED_RETURN` 在基线门下 **arm9 绿**。

### 2.3 C3.2（P1，假阳性 + 潜在漏检）

`branch_body_at` 的旧读法：跳过箭头后的空白，**只有首字符是 `{` 才按花括号取块**，否则按"单表达式"
截到行尾。两个后果：

1. `is … Failure -> if (cond) { …; return }` 被截成 `if (cond) {` ⇒ 合法终止写法**假红**（先证：`GOOD_SB_MULTILINE_IF` arm9 RED）。
2. `text_masked.find(marker)` 只锁**全文件第一处**。当前真树只有 1 处（`grep -c` 实测），所以这是潜在漏检而非现行误判；先证：`DIRTY_SB_TWO_MARKERS` 在基线门下 **arm9 绿**（未报 fail-closed，静默判了第一处）。

### 2.4 第三条：`throw` 的判决

旧判据把 `throw` **当作掉穿**处理（先证：`GOOD_SB_THROW` arm9 RED）。任务书允许两种处置；本支选择
**接受 `throw` 为终止**（它不落穿，且把 `throw` 判红会让门对正确代码常年假红），并加 `GOOD_SB_THROW`
把这条决定钉进夹具——否则"接受 throw"只会活在注释里。

## 3 修法（阶梯第 6 级：一个终止性正则 + 一个边界原语，无新依赖）

### 3.1 终止性判据（C3.1）

```python
SB_TERMINAL_RE = re.compile(r"\breturn\b(?!\s*@)|\bthrow\b")
```

判据锚从 `\breturn\b` 换成"裸 `return` 或 `throw`"。带标签形式被负向前瞻排除；`throw` 显式接受。

### 3.2 分支体识别（C3.2）

删掉"首字符 `{` 才取块 / 否则截到行尾"的分叉，改成**从箭头后的第一个非空字符起做括号深度游走，走到分支边界**
（`_branch_body_end`）：

- 开括号 `([{` → depth+1；闭括号在 depth 0 → **边界**（属于外层构造，如内联 `when (x) { is A -> return; else -> … }`）；
- 换行且 depth 0 → 看下一非空行：缩进 ≤ 箭头列 **且** 表达式没有明显继续（上一行不以 `?:` `=` `&&` `||` 运算符
  `.` `,` `(` `[` `->` 结尾；下一行不以 `.` `?:` `&&` `||` `+` `-` `*` `/` `,` `->` 开头）→ 边界；
  `else` / `catch` / `finally` 单独成行时视为继续，**但 `else ->` 是兄弟分支，不算继续**；
- `;` 在 depth 0 → 边界（内联写法的语句分隔）；
- 走到文件尾仍有未闭合括号 → 返回 `None`，调用方 fail-closed。

这样四种形态一次覆盖：`-> { … }`、`-> if (c) { … }`、`-> when { … }`、`-> expr`（含箭头独占一行、表达式在下一行）。

### 3.3 唯一性（C3.2 第二半）

`hits = text_masked.count(marker)`；`hits != 1` ⇒ 返回 problem 并**报出实际次数**
（`found N occurrences … cannot tell which one is the refresh path`）。0 处走原来的"分支消失"文案。

### 3.4 冻结面

- check 名未变：`arm9 browser refresh treats a failed download as terminal`；
- 三条 problem 文案骨架保留（`not found … (ROT — update this gate)` / `never closes (unbalanced …)`），
  第二条把 `unbalanced braces` 改成 `unbalanced brackets`（读法不再只认花括号）；
- 失败文案从 `has no \`return\` in its body` 改为 `has no terminating \`return\` / \`throw\` in its body (a labeled \`return@…\` exits the enclosing lambda only)`。
  `grep -n "arm9 browser refresh treats\|has no \`return\`" scripts/scan/test_scan.py` **无命中**（test_scan 只断言
  `SKILL_FRONTMATTER_ROUNDTRIP_SELFTEST=PASS` 这一行 + 真树 rc=0，`:2919`），故措辞改动不影响夹具。

## 6 残留（**不修，建议登记**）

1. **终止性仍是文本级判据，不是控制流**：分支体里任何位置出现裸 `return` / `throw` 就判终止，包括只在某个 `if`
   分支里返回的写法（`if (x) { return }` 之后仍会落穿）。要根治需要表达式级的路径分析（本门无此装置）。
   判级 P2：`when` 分支要落穿必须"根本没有 return"，而这类半覆盖写法在真树不存在（`grep` 实测）。
2. **嵌套 lambda 里的非局部 return 也满足判据**：`list.forEach { if (…) return }`（inline lambda 的非局部返回
   确实能退出外层函数，所以不算假绿；但 `return@forEach` 会被正确排除）。无现实形态，P2。
3. **`else` 单独成行的风格**：`} \n else {` 这种非常规换行如果缩进等于箭头列，体可能在 `else` 前被截断 ⇒ 假红。
   Kotlin 惯例是 `} else {`，当前真树与全部夹具都是 K&R 风格；已在 §7 记为未验证边界。

以上三条均**未自行登记 backlog**（本支约束为"只改门 + fix-reports"）：建议主会话按 §INCR-1117b 追加，
触发条件 = 真树出现上述任一形态，或下一次 arm9 假红被归因到读法。

## 7 未验证边界

- **风格边界**：非 K&R 的 `else` / `catch` / `finally` 换行（见 §6.3）。只有"缩进 = 箭头列"时才会误截；缩进更深
  （`else` 缩进到块内）不受影响，因为缩进判定要求 ≤ 箭头列。
- **超长单行分支**：单行内联 `when` 里多个 `;` 分隔的分支，只读第一段（`;` 即边界）—— 之后的段若含 return 不被采信，
  属保守方向（可能假红，不会假绿）。
- **Kotlin 的 `when` 分支是表达式时的隐式返回**：`is Failure -> throw …` 已验证；但"分支体是 `run { … }` 里 return"
  这类包装形态未被夹具覆盖（读法上会包含整块，方向为保守）。
- 真机无涉（本支是纯静态门）。
