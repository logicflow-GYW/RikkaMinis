# RikkaMinis 开发历史档案

本目录是 RikkaMinis 开发过程的**日志合并导出**，从本地 memory 每日日志
（`/var/minis/memory/`）按时间正序聚合而成，用于开源归档。

## 三个文件，三根轴

| 文件 | 视角 | 回答的问题 |
|------|------|-----------|
| `rikkaminis-dev-history.md` | **时间轴** | 这天发生了什么 |
| `rikkaminis-dev-history-INDEX.md` | **按天索引** | 快速跳到某一天 |
| `rikkaminis-dev-history-SAGAS.md` | **主题轴** | 这件事的完整历史（跨 44 天） |

### 为什么要第三根轴

前两个文件是**一条河**：所有条目按日期排列，覆盖完整、时间线清晰。
但要回答「滚动跳动这个问题到底经历了什么」，得从 08-05 翻到 08-07 再到
08-16 再到 08-27 再到 09-13——横跨五个日期、十几条记录，**把它们串起来的
是读者的大脑**。

`-SAGAS.md` 补上缺的那根轴：**主题 → 跨日期条目串**。每个主题是一根线，
穿过时间轴，把散落的条目串成一个完整的故事，并附：

- 一段**叙事**（从发现 → 误判 → 根因 → 翻车 → 修好）
- 一个**状态**（已闭环 / 持续跟踪 / 部分放弃 / 已撤回）
- 完整的**条目表**（按时间列出该主题下的每一条）

## 说明

- 覆盖范围：2026-08-03 ～ 2026-09-15（44 天，995 条）。
- 已剔除与 RikkaMinis 开发无关的条目（其他仓库、元讨论等）。
- 已脱敏：邮箱、API 密钥、Cloudflare 账户 ID、个人域名、代理地址、
  HF 命名空间、疑似密码等均替换为占位符（`[EMAIL]` / `***CF_ACCOUNT_ID***`
  / `***DOMAIN***` / `***PROXY_ADDR***` / `***USER***` / `***PASSWORD***`）。
- 由 `skills/dev-history-sync/` 的脚本生成与脱敏，可重复执行
  （`rebuild_dev_history.py` → `sanitize_dev_history.py` →
  `build_sagas.py` → 再次 `sanitize_dev_history.py` 验证）。
  **注意：脱敏只作用于主文件，`-INDEX.md` 需单独同规则处理**（摘要截断可能
  产生半截邮箱，需一并检查）。

## 主题索引的可靠性边界

主题归属由**关键词规则**自动判定，不是人工逐条标注：

- 标题命中权重 3、正文命中权重 1，累计 ≥3 即归入；
- 「CI / 审计 / 协作 / 档案 / 上游 / 决策」这类元主题要求**标题里点名**，
  否则几乎每条都会被 `main`/`分支`/`合并` 这类样板词拉进来；
- 标题里没有主题词的收尾条目（`X 完成` / `X 收尾`——主题词在**上一条**里）
  由「12 小时内最近一条有主题的条目」**继承**归属，表格里标 `↳` 以区分
  推断与实配；
- 约 6% 的条目不属于任何主题，它们在文末列出——那是下一轮主题发现的
  第一手候选，不是错误。
